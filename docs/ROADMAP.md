# Forge Roadmap

This roadmap records product direction at a deliberately high level. It is not a closed implementation specification, acceptance checklist, or authorization to begin work.

## Phase 1 — COMPLETE

**Scope:** shell, responsive behavior, and Forge visual identity.

Phase 1 established the engineering-workstation frame, three-panel desktop hierarchy, responsive mobile tabs, PCB / FR-4 surface language, ENIG gold accents, mobile density, and status/safe-area refinements.

Status: **COMPLETE / APPROVED / MERGED** through PR #1.

## Phase 2 — PLANNED

**Direction:** Build Flow + Part Selection UX.

Potential high-level goals:

- clearer `Slot` states;
- clearer build progression;
- stronger next-step guidance;
- improved `PartCard` information hierarchy;
- more visible compatibility and conflict states;
- responsive and mobile orientation improvements.

These goals do not prescribe exact components, interactions, copy, layouts, or implementation order. Phase 2 must receive an explicit task and branch before work begins. Preserve the existing functional regression baseline while its scope is defined.

## Future phases

Possible longer-term directions include:

- Forge Score;
- Forge Insight;
- smarter recommendations;
- Compare;
- visual PC preview;
- Build Complete experience;
- saved builds;
- shareable build presentation;
- Museum expansion.

The order, names, and scope of future phases may change. Do not implement any future phase, feature, or supporting refactor without an explicit task from the user.
